# gambit — freestanding jolt nREPL unikernel

Compile the full jolt kernel (live `jolt-compile-eval`) through Gambit v4.9.7
(`gsc -target C`) into a bare-metal x86-64 ELF loaded at `0x100000`, and boot
it under libkrun as an external kernel. COM1 (`0x3F8`) is wired to host
stdin/stdout; the guest runs a **bencode nREPL endpoint**, so a host process
can evaluate jolt forms, capture their printed output, and receive values and
errors over the serial stream.

This is the green light for the jolt bare-metal lane: the whole freestanding
chain — `_start -> kmain`, FPU, COM1 serial, bump-heap malloc, the full Gambit
runtime (`___setup` + module init), and the jolt compiler — is live in a
libkrun guest with no OS and no libc.

## What boots

```text
gambit-bare: kmain
gambit-bare: calling ___setup
boot: backend target -> :gambit
BOOT-OK
SERVE: jolt COM1 nREPL endpoint
eval> (+ 1 2) => 3
eval> {:a 1 :b 2} => {:a 1, :b 2}
eval> (map inc [1 2 3]) => (2 3 4)
READY
```

After `READY` the stream is pure bencode nREPL. See
**[NREPL.md](NREPL.md)** for the full wire protocol (ops `eval`, `clone`,
`describe`, `close`; sessions; stdout capture; error rendering).

## One-command recipe

Prerequisites (already present on this host):

- `~/.local/bin/gsc` — Gambit v4.9.7, built **full**, with the full build tree
  at `/tmp/gambit-full` (`lib/*.c`, `include/*.h`).
- libkrun at `/tmp/libkrun` (for the `boot`/test steps).
- `clang` (the generated ~100MB `boot.c` makes gcc explode).

```sh
cd jolt-microvm/examples/unikernel/gambit

./stage.sh serve            # compile + link + make -> jolt-bare.elf
./stage.sh serve boot       # also boot it under libkrun

./nrepl-test.py             # boots + drives the endpoint, asserts ALL PASS
```

`./stage.sh` alone stages and builds the probe boot (`jolt-bare.elf`). Modes:

| Mode | Scheme source | Result |
|---|---|---|
| `probe` (default) | `kernel-probe.scm` | 2-line `BOOT-OK` green light |
| `full` | `unikernel-main.scm` (boot-repl profile) | `BOOT-OK` + compiler smoke |
| `serve` | `boot-probe.scm` + `serve.scm` | `BOOT-OK` + COM1 nREPL endpoint |

## What each file is

| File | Role |
|---|---|
| `NREPL.md` | COM1 nREPL wire protocol reference |
| `nrepl-test.py` | boots the ELF, drives bencode, asserts eval/out/err/sessions |
| `stage.sh` | `probe` / `full` / `serve` staging + build + boot |
| `kernel-probe.scm` | the probe Scheme program: `(display "BOOT-OK\n")` |
| `kmain.c` | freestanding entry: FPU + COM1 + `___setup` |
| `bare_os.c` | bump-heap malloc + 16550 COM1 UART |
| `bare_libc.c` | mem*/str*/math the generated C needs |
| `bare_stubs.c` | setjmp/longjmp + ~100 POSIX stubs; write -> COM1 |
| `entry.S` / `idt.c` / `idt.S` | `_start` + 32-vector fault dumper |
| `shim.h` | force-included declarations for the generated C |
| `booter.c` | libkrun external-kernel loader (host side) |
| `Makefile` | builds `jolt-bare.elf` from `src/` + the files above |

The nREPL server source lives in the jolt host repo:
`jolt-lang/host/gambit/serve.scm` (bencode codec + nREPL loop) and
`jolt-lang/host/gambit/boot-probe.scm` (full-profile boot with the live
compiler). `src/` and `include/` are generated by `stage.sh` and not vendored
(~34 MB of generated C).

## The one bug worth knowing

`kmain.c` passes the **linkfile** linker `___LNK_serve__` (double underscore)
to `___setup`. Passing a **module** linker (single underscore) makes
`setup_modules` see one module instead of the whole tree, every global's `.prm`
stays at its hash sentinel, and the first `___JUMPPRM(##with-exception-catcher)`
jumps into the hash -> EXC 14.
